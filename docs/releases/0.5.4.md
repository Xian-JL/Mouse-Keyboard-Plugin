# 0.5.4 发布记录

日期：2026-11-18。规格：1.12.0。基线：0.5.3。

## 中文IME输入准确性

根据更新文档11.9修复ASCII扫描码在中文IME下变字、吞空格或改成全角标点的问题；不再调整键速和指针采样参数。用户关于网站采集/检测的判断不作为本版保证。

begin在未选择目标时报告inputLayout.pending，避免改动前台DSH本身。首次已授权目标前置后、快照和任何键鼠动作之前，使用系统已经加载的US键盘句柄，通过WM_INPUTLANGCHANGEREQUEST请求焦点及必要主窗线程切换；核验双方GetKeyboardLayout为0x04090409、非IME且没有已观测native模式。一次run仅首次准备允许请求，后续键盘动作只校验，回到中文则拒绝并给出手动Win+Space切ENG的明确提示。所有新按下仍通过检查，已发送部分保留partial且不重放。

不调用LoadKeyboardLayout或ActivateKeyboardLayout，不新增布局、修改区域设置/热键或注入Win组合键。选择此实现是因为[Microsoft LoadKeyboardLayout文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-loadkeyboardlayoutw)说明该API可能加载/激活系统布局；本版按[GetKeyboardLayoutList](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getkeyboardlayoutlist)查询现有句柄，按[WM_INPUTLANGCHANGEREQUEST](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-inputlangchangerequest)发出可被应用拒绝的请求，并复查结果。

默认不恢复原布局。观察、动作humanization、status和end提供from/to/current、changed、attempted、verified、restored等有界目标线程事实；目标消失则unknown/current=null。状态是目标最近核验或结束只读结果，不是系统全局永久保证。已入队的布局请求不能撤回，取消后不会继续发请求或新按键，不承诺撤销目标已经收到的系统消息。

auto与显式unicode保留；可编辑控件中的精确命令/路径/代码优先显式unicode，画布/终端保留需要的键语义。所有键盘通道均做布局预检，Unicode不被当作每种应用都支持的保证。四工具、按键白名单、±2px、像素/命中、Esc锁存、用户仲裁、文本纠错门控及原注入标记保持。

## 验证范围

新增LAYOUT-01可控平台覆盖一次准备、已为英文、无US、请求拒绝/超时、native模式、线程变化、Esc/用户活动、人工恢复、多目标和结束未知状态。LAYOUT-02覆盖Host/Bridge有界元数据、中文人工提示、partial不重试和新run清除旧布局。旧回归、原生编译、SDK及确切包检查保持，结果见0.5.4-validation.json。

本轮不操控用户桌面，不调用实际布局切换API；所有自动开关循环在没有目标时保持pending。没有把协调器模拟、普通输入计划或计时探针当成WinUI/浏览器/画布实机IME验证。真实0.5.4输入、物理Esc、TSF/IMM兼容及布局结束状态仍需用户按manual.md复验，未测项NOT_RUN。

## 安装

```powershell
dsh plugin --profile desktop add https://github.com/Xian-JL/Mouse-Keyboard-Plugin/releases/download/v0.5.4/mouse-keyboard-plugin-0.5.4.tgz
```

完整退出并重启DSH后加载新Host和Helper。旧配置保留，没有新增设置项。
